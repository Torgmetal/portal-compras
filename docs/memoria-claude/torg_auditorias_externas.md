`/qualidade/auditorias` (model **`Auditoria`** + `AuditoriaDoc`) — ≠ Auditorias Internas (`AuditoriaInterna`, RAI). É a auditoria de CERTIFICADORA/cliente sobre a Torg.

**Duas partes:**
1. **Portal do auditor (já existia):** cada auditoria tem `mensagemBoasVindas` + `capaUrl` (foto) + documentos (`AuditoriaDoc` tipo SOLICITACAO/EVIDENCIA) + checklist GQ-FQ-003 (`checklistJson`). Publica (`publicar`) + envia e-mail (`enviar-email`) → auditor vê em `/portal-cliente/[token]` (`/api/qualidade/auditorias/portal/[token]`), sem login, **só os documentos EVIDENCIA**. É o "link com mensagem/foto" que o Vitor pedia — já estava pronto.
2. **Relatório INTERNO (novo 13/08, commit e7b00fb):** campos no `Auditoria` — `numero` (RAE-nnn, atribuído na 1ª vez com conteúdo), `dataAuditoria`, `auditor`, `norma`, `escopo`, `constatacoes` (Conforme/Não-conforme/Melhoria, reusa `lib/auditoria-interna`), **`planoAcao` = 5W2H PRÓPRIO** (embutido, NÃO o `PlanoAcao`/PA compartilhado — decisão do Vitor), `fotos`, `conclusao`, `relatorioEmitidoEm`. PDF padrão Torg em `lib/auditoria-externa-pdf.js` (espelha `auditoria-interna-pdf`). Rota `GET /[id]/pdf`; PATCH `/[id]` estendido. Tela: card "Relatório da auditoria (uso interno)" no `AuditoriaDetalheClient.jsx` (fotos reduzidas no browser via canvas). **Relatório/plano ficam INTERNOS** — não vão ao portal do auditor.

**Reforma dos documentos (15/08, commit ea52a7b) — Etapa 1:** a parte de "mostrar docs ao auditor" estava bagunçada (docs num card + checklist de status noutro). Unificado:

Docs sem `requisito` caem em "Outros documentos (sem item)". Seção "Evidências adicionais (pedido a mais)": itens do usuário (título + arquivos), docs ligam via `requisito=item.id`.
