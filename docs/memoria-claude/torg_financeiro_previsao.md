Aba **`/financeiro/previsao`** (nova, 08/2026; requireRole ADMIN/FINANCEIRO/COMERCIAL): previsibilidade de caixa. **Valor previsto de cada carga = peso × R$/kg** OU, quando o pedido é **por peça**, **nº de peças × R$/peça**; agrupado por mês = o fluxo de faturamento.

**Base de faturamento por carga (peça vs kg)**: a previsão escolhe por OP pela **UNIDADE** das linhas de receita (`ehPeca` = unidade ∈ pç/un/cj/peça… normalizada; `PECA_UNITS` no route). Se a OP tem linha por-peça: `R$/peça = Σ(valor das linhas por-peça) ÷ Σ(qtd)` e a carga vale `nº de peças × R$/peça` (nº peças = Σ `qtdPlanejada` dos itens `tipo=PECA` da PlanejamentoCarga). Senão, POR KG (`peso × OP.valorFaturarPorKg`). Unidades não-peça (kg/m²/vb) NÃO viram base de carga (a carga fica em aberto se a OP não tem R$/kg). Lógica em `opBase`; tabela mostra "Peso / Peças" + "R$ unit." (kg ou /pç). PENDENTE possível (v2): preço POR MARCA (linha↔marca) quando os preços variam muito por tipo de peça — hoje, se há várias linhas por-peça com preços diferentes, o R$/peça ainda é a média delas.

- **Data + peso da carga** vêm da **`PlanejamentoCarga`** (a "Programação de Cargas" da Expedição): `dataPrevista` + peso estimado (Σ `PlanejamentoCargaItem.pesoEstimadoKg`). Peso **real** = `Romaneio.pesoRealKg` quando a carga já tem romaneio (`romaneioId`, status CONCLUIDO). NÃO vem do cronograma — as tarefas "1ª/2ª Carga" do cronograma NÃO têm vínculo com carga/romaneio (`CronogramaTarefa` sem cargaId).
- **Receitas do contrato por linha (pedido de venda)**: a seção "Receitas do contrato" no detalhe da OP (Comercial, `OPDetailClient` → `ModalReceita`/`ReceitasTabela`; API `/api/comercial/op/[id]/receita` + `/api/comercial/receita/[id]`) espelha o pedido de compra do cliente. Cada `OPReceita` é **`tipoPreco`** VALOR (fechado) | **POR_UNIDADE** com uma **`unidade`** de medida LIVRE (pç, kg, t, m, m², un, cj, vb…) + **`quantidade`** + **`valorUnitario`**; o `valor` da linha é DERIVADO (qtd × unitário) server-side. O Comercial preenche **manual, linha a linha** (feedback do Vitor: manual evita o erro da média). POR_KG/POR_PECA são legado (aceitos e mapeados p/ POR_UNIDADE+unidade). Várias linhas = o pedido de compra. **Σ receitas.valor = o contrato** (usado como contrato implícito quando `OP.valorTotalContrato` é nulo) e alimenta previsão/margem. Colunas via SQL idempotente (ensure-mes-tables). Isto é DIFERENTE do R$/kg único da OP abaixo (que é a base da previsão POR CARGA):
- **R$/kg** = campo NOVO **`OP.valorFaturarPorKg`** (coluna criada via SQL + garantida no `scripts/ensure-mes-tables.mjs`; db push é bloqueado por drift). O **Comercial preenche no cadastro da OP** — modal "Editar OP" (`OPDetailClient.jsx` `ModalEditarOP`), ao lado do valor de contrato; PATCH `/api/comercial/op/[id]` (schema + dataUpdate). Atalho: também dá pra editar no painel "R$/kg por obra" da própria aba de Previsão (mesmo campo). Sem R$/kg OU sem peso → carga fica **"em aberto"** (só a data).
- API `/api/financeiro/previsao`: GET devolve `{cargas, canceladas, porMes, ops(ativas), totalPrevisto, totalReal, nAberto}`; PATCH `{opId, valorFaturarPorKg}`. Entrada no `SidebarFinanceiro.jsx`.

**Status/situação da carga** (mostrado no Financeiro, por carga): `statusCarga()` deriva na precedência **Cancelada → Emitida → Alterada → Atrasada → Confirmada → Pendente**. Automáticos: Emitida (`romaneio` ou `status=CONCLUIDO`), Atrasada (venceu sem romaneio), Alterada (`dataPrevista != dataOriginal`, mostra a nova data). Manuais (Planejamento/Expedição): **Confirmada/Cancelada** via `PlanejamentoCarga.situacao` (PENDENTE/CONFIRMADA/CANCELADA) — campo novo + `dataOriginal` (colunas via SQL + ensure-mes-tables); Cancelada some do total mas fica numa seção "Cargas canceladas" (registro). Seletor de situação por carga na **Programação de Cargas** (`ProgramacaoCargasClient`); PATCH `/api/expedicao/planejamento/[id]` aceita `situacao` (acesso ADMIN/EXPEDICAO/PLANEJAMENTO). Cancelamento OPERACIONAL (`status=CANCELADO`) segue ADMIN-only; o `situacao=CANCELADA` é o cancelamento de PREVISÃO (Planejamento).

**Onde nasce a carga (ownership, esclarecido pelo Vitor):** o Planejamento é quem **define as peças/entregas** que vão pra obra ("a lista de prioridade do Comercial vira várias entregas — nem tudo cabe numa carga"); a **Expedição certifica** que aquilo vai mesmo e emite o romaneio; o **Financeiro só enxerga** a previsão. Página **`/planejamento/programacao-cargas`** (nova, 08/2026; role ADMIN/PLANEJAMENTO/EXPEDICAO): seletor de OP → **reaproveita o `PlanejamentoCargaSection`** do checklist da Expedição (prop nova `defaultAberta`) pra criar/editar/listar as cargas da OP. Liberado PLANEJAMENTO em: `GET /api/expedicao/checklist`, `GET/POST /api/expedicao/planejamento`. A fonte da previsão continua a **PlanejamentoCarga** (Vitor confirmou "Da Programação de Cargas" — NÃO é o `RomaneioPrevio` do Comercial, que é uma lista de prioridade, coisa diferente).
