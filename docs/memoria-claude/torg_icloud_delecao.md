O `portal-compras` mora em `~/Desktop/Claude Test` = pasta **sincronizada pelo iCloud**. O iCloud não evacua só `node_modules` (erro `Cannot find module '@next/env'` no build → `npm install`): ele **remove arquivos-fonte** da árvore local e cria **cópias duplicadas com " 2"** no nome (ex.: `app/compras/fornecedores 2/`, `app/compras/rm 2/`, `app/data-book/assinar/[token] 2/` — untracked, não vão pro git/prod, mas poluem o build).

**Incidente 30/06/2026 (descoberto) — apagão de produção de ~2 dias:** o commit `6b9ef93` (cuja mudança real era SÓ `lib/conjuntos-setor.js`, os furos de Acabamento) **capturou a deleção de 9 arquivos** de `app/fornecedores/{c,estudo,frete,entrega}/[token]` — o portal público inteiro do fornecedor. Os arquivos tinham sumido localmente (iCloud) e um `git add` em massa registrou a remoção. Resultado: **todo link `/fornecedores/c/<token>` enviado aos fornecedores dava 404 em produção desde 28/06** — ninguém conseguia abrir/responder cotação. O Safari esconde o path na barra (mostra só `workspace.torg.com.br`), o que disfarçou (parecia a home). Corrigido: `git checkout 6b9ef93^ -- app/fornecedores/{c,entrega,estudo,frete}` → build → commit só desses 9 arquivos → deploy `39f1958` (404→200 confirmado em prod).

**Incidente 06/07/2026 — escalou e ficou PERIGOSO (numa só sessão):** o iCloud (a) deletou o módulo **`app/rm`** (Engenharia) inteiro **DUAS vezes**, criando lixo `app/rm(1)/`, `app/rm(2)/` e `app/[id](1)/`, `app/nova/` (padrão novo: sufixo **`(N)`**, não só " 2"; e às vezes **espalha** os subdirs — `[id]` e `nova` viram pastas soltas na raiz de `app/`); (b) **RENOMEOU a rota do NextAuth** `app/api/auth/[...nextauth]` → **`[._.nextauth]`** — os `...` viraram `._.` → **quebraria o login em produção** se commitado sem olhar (o build acusou "Segment names may not start with erroneous periods ('._.nextauth')"); (c) criou arquivos **`._*`** (AppleDouble) que o Next tenta tratar como rota e **quebram o build**; (d) evacuou `node_modules`/`prisma` binary ~3x. Tudo restaurado do git (`git restore app/rm` / `git restore "app/api/auth/[...nextauth]/route.js"`) + `rm -rf` do lixo, e **nada de corrupção foi commitado** (conferindo `git status` antes de cada commit). ⚠️ **Recomendação virou urgente: mover o repo pra fora do `~/Desktop`/iCloud** (o Vitor foi avisado; aguarda decisão).

**Incidente 10/07/2026 — o iCloud também TRAVA git+build (não só apaga) → REPO MOVIDO:** `next build` e `git fetch/commit/push` **penduram** (0% CPU, nada escrito em `.next`/`.git`). `sample` do processo mostrou `uv__threadpool_cleanup → uv_thread_join → __ulock_wait` = **thread do libuv presa numa syscall de `fs` esperando o daemon do iCloud (bird/cloudd)**. Reboot, `killall bird cloudd`, `rm -rf .next` e limpar cache **NÃO resolveram**. **RESOLVIDO tirando do iCloud:** `git clone git@github.com:Torgmetal/portal-compras.git ~/dev/portal-compras` clonou em **3,7s** (vs 90s+ travando) e commit/push viraram instantâneos. ⚠️ **A cópia de trabalho canônica agora é `~/dev/portal-compras` (FORA do iCloud). Trabalhar SEMPRE lá.** A do `~/Desktop/Claude Test/portal-compras` (iCloud) só serve de backup e pode ser apagada — o remoto tem tudo. (Um commit que estava só local no Desktop, `78076dc`, foi trazido pro clone copiando os 7 arquivos e repushado como `6b872de`.)

**Why:** sob iCloud, o working tree pode estar **incompleto ou renomeado sem aviso** e as operações de `fs` (git/build) **penduram** esperando o daemon do iCloud; `git add -A` / `git commit -a` transforma uma evicção/renomeação silenciosa em deleção commitada e deployada — e agora já vimos corrupção que quebraria **login** (NextAuth), não só páginas.

**How to apply:**
- **Nunca** `git add -A` nem `git commit -a` neste repo. Stagear **caminhos explícitos** do que você editou.
- **Antes de todo commit**, conferir `git status` e `git diff --cached --name-only` — se aparecer `D` (deleted) de arquivo que você não mexeu, é evicção do iCloud: NÃO comitar, restaurar com `git checkout HEAD -- <path>`.
- Build/dev falhando por módulo ausente (ex.: `Can't resolve './lib/agent'`, `abort-controller` em `@anthropic-ai/sdk`) = evicção do iCloud, NÃO bug de código. Um `npm install` targetado raramente basta — as deps transitivas somem em cascata (whack-a-mole); prefira `rm -rf node_modules && npm install`. Importante: o **build de produção externa o node_modules** (passa mesmo com deps locais evacuadas) e a **Vercel instala limpo**, então **prod fica OK** — quando o dev local estiver nesse estado, dá pra validar runtime **contra a produção** (ex.: o endpoint público `/api/parse-cotacao-ai`) em vez de brigar com o local.
- 404 inesperado em prod → `git log --diff-filter=D --oneline -- <rota>` pra achar deleção acidental; restaurar de `<commit_da_delecao>^`.
- Lixo seguro de remover (untracked): pastas **" 2"** e **"(N)"** (ex.: `app/rm(2)`), subdirs soltos que o iCloud espalhou, e arquivos **`._*`** (AppleDouble — `find . -name '._*' -not -path './node_modules/*' -delete`; quebram o build do Next).
- **Antes de todo build/deploy**, checar dano estrutural: `git status --short | grep -E '^ ?D|\(1\)|\(2\)|\._|\[\._'` e confirmar que **`app/api/auth/[...nextauth]`** existe (não `[._.nextauth]`) — restaurar com `git restore` o que estiver deletado/renomeado.
- **Alterar schema/tabela sob esse repo:** se `prisma db push` acusar drop de colunas que você não mexeu (drift do banco vs schema.prisma, ex.: Ferias/Ponto do Matheus), **NÃO** use `--accept-data-loss`; crie suas tabelas por **SQL direto** (`CREATE TABLE IF NOT EXISTS` via `$executeRawUnsafe` na conexão unpooled) + `prisma generate`.
