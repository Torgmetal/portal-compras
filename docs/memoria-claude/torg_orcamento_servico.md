- **Modelo `OrcamentoServico`** (SQL cru — cuidado drift): `numero` (OS-001), cliente/obra/contato, `servicos` JSON (CORTE_FURACAO/JATEAMENTO/PINTURA/SOLDA — `lib/orcamento-servico.js`), `status`, `valor`, `observacoes`, `opId`, `composicao` JSON por serviço.

**Composição corte/furação (PRONTO 07/07):**
- `CatalogoPerfilEstrutura` POPULADO (123 perfis W/HP, kg/m; W embute o kg/m no nome).
- Tabela: perfil + comprimento + qtd barras → **peso** (kg/m×compr×qtd); **tempo médio (min/barra)** informado → tempo total.
- **Preço por hora OU por kg** (seletor no card de custo, 07/07): hora → tempo×R$/h; kg → peso×R$/kg. Mostra a equivalência dos dois lados. Grava em `composicao.CORTE_FURACAO` (metodoPreco, precoKg, material, espessura) + `OrcamentoServico.valor`.
- **Valor/hora puxa do custo-hora** (07/07): `lib/custo-hora-calc.js` calcula a preço-hora do setor e casa por palavra-chave (corte→PREPARAÇÃO, jato→JATO, pintura→PINTURA, solda→SOLDAGEM); auto-preenche o campo. No modo kg sugere o R$/kg equivalente.
- Campos: **email/telefone/endereco** (Dados) + **diasPagamento** (Resumo) — colunas via SQL.

**Custo-hora por setor** — modelo detalhado migrou pra [[torg_custo_hora]] (overhead agora = ADM folha + outros custos operacionais da DRE, NÃO mais o "1,5 mi chapado"; flag faturaHora; horas manuais).

**Gerar proposta PTC (07/07):** aba **Resumo / Proposta** (tabela padrão + composição do preço margem/impostos). Botão gera o **.docx** preenchendo uma cópia do template PTC (`templates/proposta-servico.docx` re-tagueado com docxtemplater, embutido base64 em `lib/proposta-template-b64.js`; gerador em `lib/proposta-servico-docx.js`; rota `/[id]/proposta?formato=docx|pdf`). Regras: fontes pretas, **blocos condicionais por serviço** (só entra o selecionado), documentos referentes = nomes dos arquivos anexados, perfis na descrição do corte, CQ por serviço (corte=dimensional; solda=+visual soldagem), tabela só com serviços ofertados, dias de pagamento variável. PTC auto = `PTC-{OS}-26`.
- **PDF direto via pdf-lib** (`lib/proposta-servico-pdf.js`, `gerarPropostaPDF`) — recria a PTC em PDF nativo no padrão Torg (navy/laranja, seções, tabela de preços+revisões, assinaturas), igual aos outros PDFs do portal. **Formatação ABNT (NBR 14724, 10/07):** margens 3 cm esq/sup × 2 cm dir/inf, corpo 11pt **justificado** (cada palavra posicionada no x → extração sai palavra-por-linha, mas visual OK) com recuo de 1ª linha ~1,25 cm, entrelinha 1,5, seções numeradas (1.1/2.3…) em negrito, paginação "x / n" no rodapé. **NÃO usa CloudConvert** (abandonado — só 1 projeto Vercel, sem key pra herdar; os outros PDFs do portal são pdf-lib, não conversão). Sanitizador WinAnsi. `lib/cloudconvert.js` ficou como código morto. Não é byte-idêntico ao .docx (Vitor aceitou).
- **Envio ao cliente** (rota `/[id]/enviar`, 07/07): gera PDF + manda por Resend com saudação formal, nº+revisão no assunto, mensagem estratégica editável, **CC do comercial** (via `/api/relatorios/emails`), anexo PDF. `sendEmail` ganhou `fromName` → vai como "Torg Metal - Comercial" (não "Workspace"). Registra enviadoEm/status ENVIADO/envios; 1º envio grava R00.
- **Revisões** (rota `/[id]/revisao`): número (R00/R01…) + data automáticos; motivo **obrigatório**; só depois de enviado. Reenvio simples NÃO sobe revisão. Tabela de revisão do Word é loop; nº inclui `-R00`. Colunas `revisao/revisoes/enviadoEm/envios` (SQL). PIT (ANEXO I) removido do template; marcadores de lista forçados em preto.

**Fluxo de fechamento (10/07):** **Consolidação** (botão Consolidar → `consolidadaEm`, badge + tarja verde "PROPOSTA CONSOLIDADA" no PDF; "Desfazer" até haver aceite; colunas consolidadaEm/aceiteToken/aceito*/opCriadaId por SQL). **Pagamento livre**: campo texto `pagamentoPrazo` ("15", "28/42", "30/60"…) — vira "X dias" na proposta (era Int diasPagamento). **Inclusos/Exclusos editáveis**: aba nova; `inclusos`/`exclusos` JSON (null=padrão de `lib/proposta-textos.js`); pdf-lib usa a lista custom (docx ainda hardcoded — falta re-tag com loop).
